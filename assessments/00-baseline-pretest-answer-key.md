## Short Answer Rubric

Give `1` point when the answer is accurate enough to guide learning. Give `0.5`
when the direction is right but vague. Give `0` when the answer is missing or
unsafe.

Expected ideas:

26. Written permission, defined target, allowed methods, time window, reporting
    path, and stop conditions.
27. Scanning identifies reachable hosts/services; enumeration extracts more
    detailed names, accounts, services, shares, or configuration clues.
28. Context, exposure, compensating controls, false positives, business impact,
    exploitability, and remediation priority.
29. Least privilege, credential hygiene, patching, monitoring, segmentation, and
    removing persistence paths.
30. Urgency, mismatched sender, unusual link, attachment pressure, credential
    request, or out-of-band payment/change request.
31. Session tokens represent user identity; weak tokens, insecure storage, or
    missing expiration can let attackers impersonate users.
32. Authentication failures, unusual paths, error spikes, suspicious user agents,
    unexpected methods, admin access, and abnormal response codes.
33. Untrusted input changes database query meaning; prevention uses
    parameterized queries and safe validation.
34. WPA2/WPA3, strong passphrases, enterprise authentication, guest separation,
    rogue AP detection, or disabling weak protocols.
35. Physical safety, long device lifetimes, fragile patching, firmware risk,
    segmentation needs, and operational downtime constraints.
36. Identity and access management, data configuration, logging, network rules,
    application security, or tenant-side storage permissions.
37. Encryption is reversible with a key; hashing is one-way for integrity or
    comparison.
38. It shows observable packets, protocols, timing, flow, and anomalies; it does
    not perfectly prove human intent or all endpoint state.
39. Core risk, vocabulary, evidence, defensive control, weak topic, and next
    action.
40. Any honest weak-area statement is acceptable.
