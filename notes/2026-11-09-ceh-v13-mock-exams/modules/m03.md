## State follows a probe and vantage

Host discovery asks whether a host responds to selected probes. Port scanning asks whether a transport endpoint behaves as listening, closed or filtered. Service detection asks what application responds. OS fingerprinting compares stack behavior. A service banner is a software claim, not proof of the OS or an applicable CVE. Working HTTP with no Echo Reply means ping silence did not establish that the host was down.

| Probe | Typical observation | Defensible interpretation |
| --- | --- | --- |
| TCP SYN | SYN/ACK | Open TCP listener from this vantage |
| TCP SYN | RST | Closed port |
| FIN/NULL/Xmas | RST | Usually closed on a supporting stack |
| FIN/NULL/Xmas | Silence | Open or filtered; stack behavior matters |
| UDP | ICMP type 3/code 3 | Closed UDP port |
| UDP | Silence | Open/no application reply, loss, rate limit or filtering |
| ACK | RST | Reachable/unfiltered for this probe; not proof of an open service |

## Flags and limitations

-sS selects half-open SYN scanning; -sT uses OS connect sockets; -sU selects UDP; -O requests OS detection; -sV probes service versions; -sn suppresses port scanning; -PE requests Echo discovery. Local Ethernet discovery may still use ARP. Xmas specifically sets FIN/PSH/URG; NULL sets no TCP flags. A phrase such as unusual flags cannot distinguish FIN from Xmas.

MAC spoofing applies to suitable raw Ethernet frames and stays local-link in meaning. The supplied -sT --spoof-mac combination does not establish spoofing of connect-scan traffic. Idle scanning needs an appropriate zombie/IPID behavior. Decoys complicate attribution but remain scans. Slow timing may reduce a rate alarm; it cannot open a port blocked by policy or guarantee invisibility. -T5 favors aggressive timing and may sacrifice reliability.

## Path and control traffic

Traceroute can send UDP, ICMP or TCP probes and infer hops using ICMP Time Exceeded replies. Shared intermediate hops suggest topology but do not authenticate it. Selective ICMP filtering should preserve required error signaling: IPv4 type 3/code 4 supports classic path-MTU discovery. Blocking every type-3 response can break ordinary traffic.

Example: a NULL probe is silent. Record the probe, capture position and retry/loss conditions, then use a separately permitted corroborating method. The evidence supports ambiguity until the additional observation resolves it.

## Selected primary checks

- [R01: Nmap: Firewall/IDS Evasion and Spoofing](../references.md#r01): MAC spoofing affects raw Ethernet scans, not connection-oriented features; fragment/evasion claims have implementation limits.
- [R02: Nmap: Port Scanning Techniques](../references.md#r02): Scan type, returned packets and target-stack behavior determine state interpretation; FIN/NULL/Xmas are not universal invisibility techniques.
- [R03: RFC 1191: Path MTU Discovery](../references.md#r03): IPv4 fragmentation-needed ICMP errors support classic path-MTU discovery, so blocking every type-3 message can impair connectivity.
