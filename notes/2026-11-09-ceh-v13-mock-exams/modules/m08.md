## Capture and redirection

Passive capture observes traffic visible at an interface. Active interception changes forwarding or name/configuration state. Promiscuous mode does not make a switch deliver every unicast frame to the capture port. A mirror/TAP, local redirection or an actual flooding behavior supplies a vantage; encrypted application data may remain protected. Wireshark Follow TCP Stream reconstructs captured stream bytes, while display filters select already captured packets. tcpdump provides command-line capture.

| Mechanism | State changed | Evidence to inspect |
| --- | --- | --- |
| ARP poisoning | Host IP-to-MAC mapping | Conflicting replies, gateway bindings, switch position |
| MAC flooding | Switch MAC-to-port table pressure | Source-MAC churn and unknown-unicast flooding |
| Rogue DHCP | Client lease options | Offer/ACK sender and gateway/DNS values |
| DHCP starvation | Lease-pool availability | Large client-identity/request rate and exhausted leases |
| STP manipulation | Layer-2 root/path selection | Superior BPDUs and topology events |

## Controls and boundaries

DHCP snooping must be enabled for the relevant context with trust limited to legitimate server/uplink ports. DAI validates ARP using binding/ACL data; it does not simply mean enabling DHCP snooping. Root Guard rejects superior root claims on designated ports; BPDU Guard disables an edge port that receives BPDUs. Choose from actual port roles. Port security and NAC binding can reduce unauthorized learning/bridging; authenticated session inheritance remains a possible design gap to evaluate.

MAC-table pressure can flood unknown unicast within a VLAN; it does not automatically cross VLAN boundaries. Many learned MACs on a port can also be legitimate behind a switch or virtualized host. Classic switch-port stealing targets MAC-to-port learning and differs from racing ARP replies at a host. Wrong-MAC ping and similar sniffer-detection methods are implementation-dependent heuristics; a silent passive observer may give no response.

Example: users receive new DNS/gateway options and reach a fake portal. Inspect DHCP replies first. If the pool is exhausted rather than wrongly configured, starvation is the more direct mechanism. This diagnosis selects a control and a verification target without treating all LAN anomalies as ARP poisoning.
