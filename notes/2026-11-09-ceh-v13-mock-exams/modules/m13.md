## Components and exposure

The HTTP server accepts requests and dispatches handlers/modules. Document root maps published content to filesystem resources. Application servers implement application behavior; virtual hosting can serve multiple names on shared infrastructure. Keep secrets outside served paths, restrict the service account, remove unnecessary services and patch applicable components. Moving a directory or rotating IPs does not repair an underlying flaw.

Banner grabbing reads claimed software/version information. Fingerprinting compares protocol responses. Website mirroring retrieves pages/resources for local analysis, still requiring initial active retrieval. robots.txt describes crawler preferences; Disallow paths are public clues and never implement authentication. A conventional HTTP deployment uses TCP 80/443, while HTTP/3 can also use UDP 443. PUT creates/replaces a target resource; multipart browser uploads often use POST.

## Input and parser boundaries

Path traversal escapes an intended filesystem root. LFI passes a local path to an inclusion sink; RFI passes an external resource where runtime configuration permits it. Reading a file does not automatically execute it. Unrestricted uploads create execution risk only if storage/path/handler behavior interprets the bytes as code. Validate content, isolate storage, use generated names and restrict execution permissions.

Response splitting injects delimiters or headers into outbound response structure. Request splitting/smuggling involves how frontends/backends delineate inbound requests. A stem saying one request became two does not uniquely support response splitting. Web cache poisoning causes shared cached responses to carry attacker-influenced output, often because input affecting the response is absent from the cache key. Defacement modifies visible content and primarily harms integrity.

## Component-specific evidence

An application named nginxWebUI is distinct from core Nginx. An IIS endpoint missing authentication may be an application enforcement flaw rather than a named server CVE. HTTP/2 memory growth needs a build/advisory and the relevant reset behavior to identify a specific defect. Outdated software alone cannot establish a buffer-overflow path.

Example: the origin serves a normal promotion but cached users see altered content until expiry. Compare cache keys, varied inputs and origin responses. That supports a cache-related hypothesis more directly than DNS hijacking or SQL injection.
