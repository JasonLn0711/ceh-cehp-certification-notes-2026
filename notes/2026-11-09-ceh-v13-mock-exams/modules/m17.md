## App, device and service layers

Unencrypted local files are insecure data storage when an attacker can access them; device rooting may be the access condition rather than the storage defect. Cleartext HTTP exposes session data in transit. An injection finding must name the receiving interpreter: JavaScript needs a WebView/browser sink and cannot be inferred from generic native-input handling. Overprivileged apps, insecure update channels and weak server APIs are additional independent paths.

Review app provenance, trusted signatures and requested privileges. A functional lookalike with a changed binary and extra behavior may be repackaged. Agent Smith names a historical app-replacement campaign; the label alone does not attribute a present incident. A RAT permits remote control, while spyware describes collection. A device/app administrator should minimize privileges and separate corporate data according to the platform's actual enforcement.

## Management and loss response

MDM manages device policy and supported remote actions; MAM scopes managed applications/data. Neither label guarantees control of a compromised OS. Locate/wipe requires enrollment, platform permissions and a reachable device. A lost phone also requires access-token/credential response. App reauthentication protects sensitive screens after the device is already unlocked; it addresses a different condition from a strong lock-screen passcode.

ADB is a development/debug interface. Legacy network ADB is associated with TCP 5555; modern wireless pairing modes differ. Disable or tightly restrict debugging in production. A product's APK form only means it can run on-device; successful rooting still requires the exact device/build vulnerability and boot-state conditions.

## Privilege and sensor terminology

Tethered/untethered/semi-tethered/semi-untethered describe reboot/reactivation behavior, not a universal exploit for a listed iPhone/iOS version. Semi-untethered boots normally and reactivates modifications through an on-device app. Firmware and patch support must be checked separately.

Spearphone research concerns motion-sensor effects from a loudspeaker under particular conditions; it is not proof of arbitrary microphone access. SIMjacker abuses susceptible SIM Toolkit behavior through binary messages, while smishing depends on a deceptive user-facing message. Source claims of an undetectable custom exploit, universal rooting tool or hardest mobile technique stay held.

Example: a colleague opens a financial app on an already unlocked BYOD phone. Application-level reauthentication directly addresses that case; encrypting the storage or changing the lock-screen passcode alone does not require a fresh check inside the open session.
