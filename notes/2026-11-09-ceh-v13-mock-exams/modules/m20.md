## Properties, primitives and protocols

Symmetric encryption uses shared secret keys for bulk data. Asymmetric schemes support operations such as signatures or key establishment/transport. Hashing gives a digest, while HMAC binds a digest computation to a shared key. A digital signature supports integrity and origin under trusted key/identity handling; it does not encrypt the message. A CA signs certificates, and the recipient still checks name, chain, validity and applicable revocation. S/MIME uses certificate-based email encryption/signatures.

RSA, DSA and Diffie-Hellman have different operations; describing private signing/public verification alone may not uniquely identify a signature algorithm. Blowfish has a 64-bit block and variable key length; Twofish has a 128-bit block and AES-finalist history; AES is a different standardized block cipher. Strength depends on key size, mode, nonce handling, authentication and implementation, not just the name.

Disk/container encryption protects data when the attacker lacks usable decryption access. A mounted compromised machine may expose plaintext through the application/OS. BitLocker's Windows integration and VeraCrypt's container/hidden-volume features answer product-feature questions; live encryption is not automatic incident containment. AES does not conceal packet sizes, timing or endpoints by itself.

## Attack models and leakage

Ciphertext-only gives encrypted samples; known-plaintext gives existing matching pairs; chosen-plaintext lets the adversary select inputs; chosen-ciphertext provides a suitable decryption/validity interaction. Differential cryptanalysis studies input/output differences, linear analysis statistical bit relations, meet-in-the-middle matches intermediate values and brute force searches candidates. Side channels leak implementation behavior such as timing/power. A padding oracle leaks validity information from different failures.

CRIME concerns TLS/SPDY compression, while BREACH concerns HTTP response-body compression with an exploitable shared secret/input context. Old TLS alone does not let any MitM decrypt every session. Traffic-analysis and compression leakage can survive strong content encryption. Steganography conceals data within a carrier; steganalysis investigates concealment rather than breaking a cipher.

## Long-term trust

Harvest-now-decrypt-later concerns ciphertext retained across a long confidentiality lifetime. Inventory public-key dependencies and plan supported post-quantum migration/key protection; distinguish public-key mechanisms from bulk encryption. Blockchain majority attacks alter consensus influence, eclipse attacks isolate a node's peer view and front-running changes transaction ordering; all are not cryptanalytic breaks.

Example: an attacker can replace a file and its plain SHA-256 digest. Use an independently trusted expected digest, a keyed MAC or a verified signature as appropriate. A file matching an attacker-supplied hash proves consistency with that supplied value, not an authorized origin.

## Selected primary checks

- [R06: BREACH: original research explanation](../references.md#r06): BREACH targets HTTP response compression with reflected input and a secret; CRIME's original mitigation concerns TLS/SPDY compression.
- [R16: NIST SP 800-88r2: Media Sanitization (September 2025)](../references.md#r16): Sanitization seeks infeasibility of access/recovery for a specified level of effort; avoid a universal impossible-recovery guarantee.
- [R19: RFC 8446: TLS 1.3](../references.md#r19): Content encryption is distinct from complete length/timing traffic-analysis resistance; a cipher name alone does not hide all metadata.
- [R24: NIST: Post-Quantum Cryptography project](../references.md#r24): Plan migration using supported post-quantum key-establishment/signature mechanisms and distinguish these roles from bulk symmetric encryption.
