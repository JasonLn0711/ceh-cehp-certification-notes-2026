## Cloud characteristics and responsibility

NIST's essential characteristics are on-demand self-service, broad network access, resource pooling, rapid elasticity and measured service. Provisioning without provider staff describes self-service; shared resource allocation describes pooling; metered billing describes measured service. IaaS gives customer OS/middleware control, PaaS supplies a managed application platform and SaaS supplies an application. Responsibility changes by service/contract; a provider's physical security does not remove customer identity/data responsibilities.

## Identity, metadata and governance

IAM roles/policies map authority; effective access can also depend on boundaries, resource policies, conditions and organization policy. A grant to any authenticated provider principal may include unrelated accounts. Managed/workload identity tokens and IMDS credentials carry actual granted permissions; intended metadata access is not itself a vulnerability. Restrict metadata exposure, use supported protections and minimize role authority. Compromised local code can still use its legitimate workload permissions.

Stolen API keys require revocation, use investigation and downstream persistence review. Deprovision departed users and revoke active sessions, keys and grants. Golden SAML forges assertions with stolen signing material; cloud-sync token replacement changes the sync destination. Missing telemetry is a detection gap, while unassigned responsibilities are a governance root cause. Do not collapse those two when the source changes answer options.

## Workload isolation and recovery

Containers commonly share a kernel. Elevated privileges, host mounts and weak runtime controls can permit a container escape; minimal trusted images and vulnerability scans are useful layers rather than complete isolation. Kubernetes orchestration coordinates desired workloads, while self-healing reconciles failures. Avoid service-account bearer tokens in logs; possession of a valid token permits its scoped actions. A cross-VM timing leak is a side channel, distinct from a container boundary escape.

Function-level least privilege limits a compromised serverless function's blast radius. It does not repair an insecure API or eliminate command injection. Log requests, identities and critical actions without exposing secrets. Multi-tenant isolation needs identity, execution and resource boundaries. The 3-2-1 backup model improves copy diversity; restricted access, immutability/versioning and restoration tests address tampering and recovery.

Example: a former employee can still read a bucket. Timely deprovisioning addresses the identity lifecycle. If another unrelated provider account can also read it because of a broad principal grant, repair the resource policy separately. One incident may contain both defects.

## Selected primary checks

- [R11: NIST SP 800-145: Definition of Cloud Computing](../references.md#r11): The definition separates five essential characteristics, three service models and four deployment models.
- [R21: AWS: Instance Metadata Service](../references.md#r21): IMDSv2 is session-oriented; metadata access/configuration and a workload's attached role permissions define the relevant exposure.
- [R22: Kubernetes: Security Checklist](../references.md#r22): Workload privilege, access control, secrets and runtime protections need explicit configuration; image scanning alone does not establish isolation.
