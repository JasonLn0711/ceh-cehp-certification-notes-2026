## Follow the data to its authority

Classify the sink and trust boundary. XSS sends untrusted content into executable browser context. SQL injection reaches a database interpreter. Command injection reaches an OS-command API; shell injection additionally involves a shell interpreter. LDAP injection alters directory-search logic; XXE resolves external entities through a parser. Unsafe deserialization reconstructs attacker-controlled objects with dangerous behavior. Naming the correct interpreter prevents memorizing a generic input-validation answer for every defect.

Client-side checks can be disabled or requests modified. Enforce validation, state transitions and authorization on the server. A redirect to another site does not itself prove XSS: an open redirect needs no script execution. A webshell is evidence of a compromised execution path and requires containment/root-cause repair rather than merely more periodic scans.

## Access, sessions and requests

IDOR/BOLA occurs when changing an object identifier grants unauthorized object access. Function-level authorization controls actions/endpoints; property-level controls protect fields. A valid login does not imply permission for every object. CSRF induces the browser to submit an unwanted authenticated request and does not inherently reveal a token. A predictable or retained session value belongs to the session subsystem. Keep these mechanisms distinct even when the source calls them all hijacking.

SSRF makes the server send attacker-influenced requests; a webhook is a feature that may become a request sink, not proof of SSRF. XML signature wrapping arises when signature validation and application processing select different nodes. WSDL inspection reveals operations and schemas and remains reconnaissance until an actual weakness is shown. A watering-hole attack compromises a site routinely visited by a target group; delivery can be conditional.

## Repair and evidence

Use context-specific output encoding/safe DOM sinks for XSS, parameterized APIs for interpreter input, explicit object/action checks for authorization and safe parser/deserialization configuration. A WAF can be a compensating layer, with its own parsing and coverage limits. Protect diagnostic detail in logs rather than return query strings and filesystem paths to users.

Example: changing only a dashboard ID reveals another tenant's records while the same token remains valid. That is object-level authorization failure; no SQL syntax change, elevated role or stolen password is needed.

## Selected primary checks

- [R13: OWASP: CSRF Prevention Cheat Sheet](../references.md#r13): CSRF induces unwanted authenticated requests; origin/token/SameSite controls address that mechanism separately from stealing a session identifier.
- [R14: OWASP: SQL Injection Prevention Cheat Sheet](../references.md#r14): Parameterized queries separate values from query structure; dynamic identifiers require suitable safe design and escaping is not the general preferred repair.
