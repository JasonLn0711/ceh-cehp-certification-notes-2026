## From open port to permitted information

Enumeration queries a service for objects, names, configuration or relationships after discovery. The permission context matters: anonymous access, a shared community, an authenticated user and an administrator expose different information. A port assignment suggests a service; its actual response establishes which protocol is present. Enumeration success is not equivalent to code execution or an accepted practical task.

## Service distinctions

DNS MX names mail exchangers, NS names authoritative servers and SOA provides zone metadata such as serial/refresh values. AXFR requests a specified zone transfer; an allowed transfer may reveal many records but is active interaction. DNSSEC authenticates signed data rather than encrypting queries. A nonrecursive empty NOERROR response cannot prove that no client recently accessed a name: expiry, ACLs, cache policy and response semantics also matter. Split DNS separates internal names from public responses.

LDAP searches directory objects under a base DN and filter. RootDSE namingContexts helps discover naming roots; it is not itself a filter. Anonymous reads depend on ACLs. Global Catalog provides forest-wide searches over TCP 3268, with TLS on TCP 3269; the supplied UDP label is erroneous. NetBIOS name-table queries reveal names/legacy roles; SMB/RPC provide shares and other account information under separate policies. TCP 445 is direct SMB; TCP 139 and UDP 137/138 are legacy NetBIOS services.

SNMP v1/v2c communities are shared authorization strings, not literally anonymous access. public is historically common rather than mandated by the protocol. snmpwalk traverses accessible MIB data; snmp-processes asks for process objects if supported; Wireshark passively observes packets. SNMP traps and agent queries have different directions and conventional ports.

NTP status/control queries can expose peers and implementation details, but ntpq/legacy ntpdc capabilities depend on the daemon. SMTP VRFY/EXPN/RCPT response differences may disclose accounts; STARTTLS is a different protection. NFS export discovery is distinct from successful mounting and file permission checks. FTP TCP 21 is control; passive/active data channels have additional transport details. SQL Server conventionally uses TCP 1433 and SQL Monitor is registered at 1434; observe protocol behavior before asserting identity.

Example: TCP 389 accepts a bind but denies a sensitive attribute. That is evidence that some directory access exists and an ACL is effective for that attribute; it is not evidence that the host is unreachable or the entire directory is exposed.

## Selected primary checks

- [R08: Microsoft: Windows service and port requirements](../references.md#r08): Global Catalog is listed on TCP 3268/3269; the mock's UDP label is erroneous.
- [R25: RFC 4033: DNS Security Introduction and Requirements](../references.md#r25): DNSSEC provides DNS data-origin authentication and integrity, not confidentiality or protection against every authoritative/account compromise.
- [R26: IANA: Service Name and Transport Protocol Port Number Registry](../references.md#r26): Registered service/transport assignments are identification leads; a port number does not prove the actual running application.
- [R27: OpenLDAP: ldapsearch manual](../references.md#r27): Search base, scope, filter and server URI are separate arguments; preserve malformed source commands and use complete client syntax in an authorized environment.
