## 1. CEH 的學習目標與基礎詞彙

CEH（Certified Ethical Hacker）是 EC-Council 的認證。道德駭客工作的思考順序是：**保護資產 → 辨識可能失敗 → 依授權驗證 → 保留可靠證據 → 修正並確認成效**。功能測試確認應有功能正常；安全測試也問不應被允許的操作是否可能發生。例如成績網站除了能登入，還應防止學生讀取別人成績或使用教師功能。測試可能增加負載、觸發警報或改變狀態，因此善意要落實成明確許可。

| 詞彙 | 可操作的理解 | 判讀界線 |
| --- | --- | --- |
| Host 主機 | 參與網路的電腦或運算環境 | 不限個人電腦 |
| Client／server | 提出請求者／提供服務者；server 可指軟體或執行它的機器 | 是互動角色，不是固定硬體種類 |
| IP／domain／DNS | 網路定位資訊／可記憶名稱／名稱相關資訊查詢系統 | 一個名稱不等於一台永遠固定的實體機器 |
| Port | 在傳輸協定內區分通訊端點的編號 | 開放只支持特定可接觸狀態，不能直接判定漏洞 |
| Service／protocol | 提供功能的軟體／交換訊息的規則 | FTP、SMTP 是協定，不是作業系統 |

## 2. 二十模組的完整概念地圖

模組之間形成知識依賴，實際攻擊或測試未必按章節順序發生。下表的「產物」是理解與練習方向，不是 Jason 已完成的結果；[官方範圍](../../../curriculum/official-scope-map.md)與既有[二十模組導覽](../course-overview.md#module-map)保留課綱追溯。

| 模組 | 核心問題、機制與教學例子 | 可保留的產物與更正 |
| --- | --- | --- |
| M01 Introduction to Ethical Hacking | 安全是什麼、誰能測、許可到哪裡、證據如何支持結論 | 安全目標與 ROE；工具輸出須有可解釋意義 |
| M02 Footprinting and Reconnaissance | 確認對象，蒐集足跡，整理資產及關係，再核對範圍；如正式網站、測試網站、郵件系統 | 資產線索與授權清單；兩詞有重疊，發現名稱不等於准許測試 |
| M03 Scanning Networks | 依探測和回應問主機、port、服務狀態 | 記錄來源位置、方法、時間；無回應可能是過濾或路由問題，open 不等於弱點 |
| M04 Enumeration | 對已知服務進一步查詢帳號、群組、共享資源或設定 | 協定、權限及回傳資訊；列出資料夾不等於能讀其中所有檔案 |
| M05 Vulnerability Analysis | 證據 → 候選弱點 → 成立條件 → 環境適用性 → 影響 | 版本辨識需核對修補、啟用功能與權限；版本相符是線索 |
| M06 System Hacking | 在允許的方法內確認安全界線被跨越 | 測試學生能進教師功能已可形成證據；無須修改真實成績擴大損害 |
| M07 Malware Threats | 惡意內容可能偽裝成更新、附件、閱讀器或盜版軟體 | Trojan 強調偽裝，backdoor 強調繞過正常控制；可同時存在。系統更新不保證新程式可信 |
| M08 Sniffing | 選觀察位置 → 擷取 → 篩選 → 解讀封包 | 封包可用於排障；HTTPS／TLS 內容不因被擷取而自動解密。「風暴／sleeping」依語境更正為封包／sniffing |
| M09 Social Engineering | 透過信任、習慣、壓力或工作流程引導行動；phishing 是其中一種 | 檢查獨立確認管道與付款／帳號／權限變更流程，而非只看信件外觀 |
| M10 Denial-of-Service | 消耗有限資源，使合法請求無法及時使用服務 | 頻寬可耗盡而主機仍運作；慢也可能是正常尖峰，需要流量與系統證據 |
| M11 Session Hijacking | 登入後以 session ID／token 維持互動狀態；被取得或控制後可能遭冒用 | Cookie 是常用載體，但不全是憑證；偷密碼、偷 session、AD 驗證材料分開分析 |
| M12 Evading IDS, Firewalls, and Honeypots | Firewall 控制通訊；IDS 偵測警告；IPS 可阻止；honeypot 吸引並觀察不當接觸 | 控制不是全能；此段只預告方向，沒有完整規避技術課程 |
| M13 Hacking Web Servers | 網站伺服器的軟體、部署與設定，例如 IIS／Apache／nginx | 網站段的「iOS」可能是 IIS 辨識錯誤；保留推定，不冒充逐字確定 |
| M14 Hacking Web Applications | 登入、選課、資料存取等業務邏輯與權限 | 整數欄位輸入 `10000.01` 是輸入檢查例子，未必當機；登入不等於對每筆資料有權 |
| M15 SQL Injection | 不安全拼接讓原本的資料進入 SQL 指令結構 | 參數化查詢分離指令與資料；刪除符號不能取代它。嚴重性依權限、資料與環境 |
| M16 Hacking Wireless Networks | 驗證決定誰能加入；加密保護傳輸內容 | 咖啡廳訪客可連 Wi-Fi，不應取得收銀管理權；連線、讀通訊、操作系統是不同能力 |
| M17 Hacking Mobile Platforms | Android／iOS 的權限、資料儲存與傳輸 | 公告 App 是否需要全部聯絡人？此段未提供完整平台攻防流程 |
| M18 IoT and OT Hacking | 連網設備、監控／控制實體過程的 OT，以及其中的 ICS | 溫控、輸送帶涉及可靠性與人身安全；測試／修補／重啟也須評估實體影響 |
| M19 Cloud Computing | 透過網路按需配置、快速提供與釋放共享運算資源 | 檢查建立資源、讀取資料、公開設定的權限；超過「別人的電腦」比喻，此段未展開服務模式 |
| M20 Cryptography | 密碼技術的應用；明文、密文、金鑰、加解密、公私鑰與簽章 | 私鑰簽署、公鑰驗證是非對稱用途之一；加密、雜湊與簽章處理不同問題 |

網站各層可串成：**瀏覽器 → 網站服務 → 應用邏輯／授權 → 資料庫 → 回應**。問題在哪一層，決定證據與修正責任在哪裡。來源：H1-03 至 12；授權與 SQL 參見 H1-07、08。

## 3. VM、Parrot、AD、實驗室與考試資訊

VM 是虛擬化提供的電腦環境，hypervisor 管理客體與底層資源。Ubuntu 實體主機可以執行 Windows 客體。Parrot OS 是基於 Debian 的 Linux 發行版；Parrot VM 是安裝它的 VM。「para／parent VM」可能指 Parrot，不能據此重建成 paravirtualization，也沒有依據宣稱工具數固定為 Kali 五分之一。

教學配置是同一虛擬化環境下並列 Parrot 測試 VM 與 Windows／Linux 目標 VM，而非所有目標必須裝在 Parrot 裡。原白板缺失，第一段不能還原 IP、Windows Server 分工或巢狀虛擬化；[第二段 §19](part-02.md#h2-19)補上四台 VM 名稱，仍未補齊拓樸。

AD DS 是集中管理使用者、電腦與資源，並整合驗證和存取控制的目錄服務。Domain Controller 是提供網域服務的伺服器角色。AD domain 是身分／管理架構，不宜直接等同網站網域名稱。

實驗室可用的判準：能說明每台機器角色、允許互通範圍、測試資料與恢復／重做方式。六個月線上實驗室是課堂安排的說法；個人到期日須核對購買與啟用紀錄。

講義記載 CEH 知識考試 `312-50`、125 題、4 小時、依試卷形式 60%–85% 及格門檻；本次選定[官方頁面核對](sources.md#live-checks)保留同一資訊。75% 不是固定規則。「必須坐滿一小時避免查核」「票最多的答案必然正確」「無條件退款」分別缺官方支持、推論不成立、或忽略方案條件。

64-bit 區塊、三把各 56 有效位元 DES 金鑰指歷史三金鑰 TDEA／Triple DES；辨識考題不等於推薦新系統採用。講義引 NIST SP 800-67 Rev.2 於 2024-01-01 撤回，詳 H1-16。來源：H1-01、13–16。接到[實驗室與考試英文筆記](../course-overview.md#virtualization)。

## 4. 五個安全要素與數位簽章

| 安全要素 | 成績系統中的要求 | 機制、證據與判讀 |
| --- | --- | --- |
| Confidentiality 機密性 | 甲只能看自己的成績，老師看其授課範圍 | 驗證「你是誰」之後，仍要授權檢查「能讀哪筆資料」。加密連線不會修正錯誤授權 |
| Integrity 完整性 | 允許依程序更正，拒絕學生擅改 | 授權變更規則與可偵測的不當修改／破壞；主機重開成功未證明資料正確 |
| Availability 可用性 | 在需要時及時可靠地選課或查詢 | 叢集與 failover 提供接手能力；驗收應看使用者工作、資料與網路，不只備援機亮燈 |
| Authenticity 真實性 | 公告確實來自教務處 | 來源鑑真與內容未改是不同問題；真來源也可能有日期誤植 |
| Non-repudiation 不可否認性 | 爭議時能釐清誰提交什麼 | 需要第三方可評估的來源／行為證據；畫面姓名、紙本指紋碼、Message-ID 都不足以單獨證成 |

雜湊將輸入映射為固定長度摘要；密碼學雜湊另外追求抗反推與抗碰撞等性質，不是等待解密的加密檔案。驗證流程：可信原始檔 → 計算並保護摘要 → 日後重算 → 比較。若檔案與比較摘要一起被替換，相符不能證明來源可信。

數位簽章流程：私鑰對特定電子資料簽署 → 保留原始資料與簽章 → 以對應公鑰驗證 → 查核公鑰與宣稱身分的可信關聯。憑證可承載這個關聯，仍需驗證信任關係。只列印電子文件會失去實際驗證所需材料；私鑰外洩、冒用及不可信日誌影響證據解讀，簽章不保證法律裁判結果。

加密主要服務內容保護；雜湊提供內容比較基礎；簽章連結資料與可驗證金鑰。任何機制都應說清楚信任前提。加密有運算成本，但「任何加密都讓整份檔案全程不能讀」不是通則。

來源：H1-07、12、17–23。接到[五要素](../m01-foundations.md#security-properties)、[銀行郵件證據](../m01-foundations.md#email-evidence)與[Windows 權限](part-02.md#h2-04)。

## 5. Attack、Vulnerability、Exploit、Compromise、Threat、Risk

Attack 是企圖破壞安全目標的活動；同類工具也能用於授權測試和排障，需看目的、許可、實際行為。Vulnerability 是程式、設計、設定或流程中可能被利用的缺陷；尚未有人利用也可能存在。Exploit 是利用缺陷形成效果的方法、程式或行為。Compromise 是安全已遭影響的狀態；未授權讀取成績已破壞機密性，不必等防毒或防火牆被關閉。

**缺少逐筆授權檢查（弱點）→ 利用請求讀取別人的資料（利用）→ 資料遭揭露（失陷）**。發現弱點、成功利用與證明全部資料受影響需要不同證據。Threat 是可能造成不利影響的情境／事件；risk 同時考慮可能性與影響。離線測試 VM 和真實成績系統即使弱點名稱相同，優先順序也可能不同。

來源：H1-24–26。接到[弱點與設定](../m01-foundations.md#vulnerabilities)、[9/15 weakness-to-harm](../../m05-vulnerability-analysis/lesson-01-weakness-to-harm.md)及[講義二風險](part-02.md#h2-05)。

## 6. 弱點來源與 TTP

設定錯誤：關防火牆可能讓既有服務可達，但不會憑空啟動服務。分開確認 **程式是否監聽 → 網路是否可達 → 是否有可利用問題**。不安全設計：把「登入者」全視為可信，缺少逐項授權，單改密碼長度解決不了。固有技術弱點：inherent 是固有，不是繼承；舊功能與相容性要逐項判斷，不是全部必然不安全。

端點也在保護範圍。員工電腦出事後可能形成橫向移動的起點，但後續可達性取決於權限、驗證與區隔；重灌不能取代對其他資產影響的調查。課堂談動機、方法、弱點的公式辨識不清，僅保留「效果需要成立條件」：無馬達攝影機無法靠指令實體轉動；沒有找到軟體漏洞仍需評估帳號、人員和流程。

TTP：tactic 是目的（例如 initial access）；technique 是方法類別（例如 phishing）；procedure 是某次活動的具體訊息、交付與步驟。圖書館比喻：進館目標 → 學生證門禁方法 → 某日下午到指定入口刷卡的實作。這是行為分析，不是人格或學歷診斷；模組順序也不是攻擊固定順序。

來源：H1-07、27；[既有 TTP](../m01-foundations.md#attack-categories) → [三模型比較](part-02.md#h2-01)。

## 7. 五類攻擊與防守問題

| 分類 | 觀察角度 | 應問的防守問題／更正 |
| --- | --- | --- |
| Passive | 觀察而不改變資料／系統，例如未授權竊聽 | 內容暴露多少？定義不只是「沒有連到目標」 |
| Active | 修改、偽造、干擾，例如擅改成績或服務阻斷 | 狀態如何受影響？一般連線未建立也可能發生 |
| Close-in | 實體接近提供的機會，例如陪同離開、機房門留開 | 訪客可接觸什麼、誰陪同、如何確認離場？接近不是入侵成功 |
| Insider | 既有信任與權限遭濫用，例如為工作取得資料後改作私用 | 帳號與內網位置不表示所有用法皆被允許，也非永遠最嚴重 |
| Distribution | 硬體、軟體或交付流程被動手腳 | 更新發布遭入侵時供應商也可能是受害者；可接 supply-chain compromise，不等於 DDoS |

這些分類混合行為、位置與信任角度，可以重疊。來源：H1-28–30；[既有分類與 TTP](../m01-foundations.md#attack-categories)。

## 8. 帽色、紅藍隊與行為者歸因

白帽以授權範圍進行測試；黑帽描述惡意濫用；灰帽是本課有時越界的入門標籤，不是法律分類。Script kiddie 強調對現成工具原理理解不足，不指年齡；使用工具本身不是問題，能否解釋操作、結果、風險才重要。

本課 blue hat 指受邀外部測試者；red hat 指反擊黑帽者；green hat 指願意學習的新手。這些顏色不是統一資格，反擊也要有授權。Red team 在授權演練中模擬攻擊，blue team 負責防守、觀察與應對，與紅帽／藍帽不同。評估應看路徑、偵測、影響、處置與改善。

Hacktivist、state-sponsored hacker、corporate／industrial spies、cyber terrorists 涉及目的、支持或活動語境。應先列觀察行為、受影響資產與歸因證據；國籍、宗教、政治立場不足以套標籤。錄音個案識別不足者保留未知。接到[行為者標籤](../m01-foundations.md#actor-labels)。

## 9. 授權到修復的八步流程

以下是講義教學整理，不是逐字稿原列八步。

1. **明確問題與許可**：例如「學生是否只能讀自己成績」，確認批准者、資產、允許方法與 ROE。
2. **區分 scope 與 limitations**：指定測試網站、兩帳號、時段是範圍；不用正式資料、不做 DoS、不增目標是限制。可達只是網路條件。
3. **正常基準**：甲能讀甲，乙能讀乙，未登入被拒絕。
4. **有限假設**：系統可能只相信資料編號而沒核對登入者；以測試帳號／假資料驗證。藏前端按鈕不能代替伺服器授權。
5. **證據分層**：角色、時間、條件、請求／回應支持「甲讀到乙的某筆假資料」；其他資料可能受影響是推論；全部可讀仍未驗證。
6. **可用報告**：預期規則、實際觀察、可能影響、成因與修正位置；讓接收者知道下一步，而非只交工具輸出。
7. **修正複測**：甲不能讀乙，同時仍可讀甲；安全修正與功能正常都要驗證。
8. **清理結案**：交代帳號、資料、暫時設定、未驗範圍與後續責任，停止測試。

顧問例子：指定場所、時段且有人陪同是授權條件；午休無人陪同或回家連線不能自行延伸。條件不足時先確認變更，帽色比喻不直接構成個案法律結論。技術能力（系統、網路、程式）與溝通、規則及產業理解在報告和修復階段交會。

來源：H1-07、31；[授權英文詳解](../m01-foundations.md#authorization)與[ROE 來源](../../../source/2026-09-04-antisyphon-roe-101/source.md)。

## 10. AI-assisted Hacking 與提示詞注入

分開 **模型建議 → 軟體呼叫工具 → 具權限環境執行 → 可驗證結果**。文字命令不等於執行，程式碼也不等於正確。原 SMTP／Nmap 示範不足以還原有效命令、目標或結果。

Shell 是命令解讀環境，script 是可執行的操作文字。ShellGPT 指第三方 `TheR1D/shell_gpt`；名稱不使它成為 OpenAI 官方程式。講義引文件指出有互動確認 shell 模式及可執行功能配置，實際行為依版本、模式與設定，不宜宣稱一律生成即執行。

Prompt injection 是不應有指令權限的輸入，使模型偏離原任務；外部報告夾帶行動指示是間接注入例子。信任邊界要區分「可提供資訊」與「可授權操作」。接上刪檔、資料庫修改或寄信工具後，錯誤可能成為外部影響，程度依工具能力及權限。

可控流程：先解釋和提出方案；對改狀態操作保留審查；限制工具與權限；保存實際動作／結果；外部文件不作為授權。這些措施降低風險，不保證單一過濾器阻止全部注入。就業影響或「永不取代」不是錄音能證明的結論；應辨別可草擬工作、需要證據的判斷與有權負責的決策。

來源：H1-32、33；[AI 詳解](../m01-foundations.md#ai-assisted-testing)與[跨專案連結](connections.md#trust)。

## 11. 能力收斂與可重用的一頁成果

應能區分三件事：**安全目標**（讀取／修改／無法使用／假冒／爭議證據）、**證據強度**（有回應／版本線索／利用／影響範圍）、**能力與許可**（工具能做、帳號可達、AI 願意產生，都需另核對授權與正確性）。缺白板、模糊命令與無證據個案維持未確認；正常復原機制不能直接叫秘密後門。

可在既有學習時段選用以下說明框架，本次僅備妥筆記，未填成學員成果：

| 欄位 | 成績系統教學示例 |
| --- | --- |
| 目標 | 學生只能讀自己的測試成績 |
| 授權／限制 | 指定測試網站、甲乙帳號與假資料；時間、方法和停止條件待實際 ROE |
| 正常基準 | 甲讀甲成功；無權請求拒絕 |
| 假設 | 逐筆資料授權可能缺失 |
| 驗證／證據 | 在授權情境比較甲讀甲與甲讀乙，保存角色、條件、請求／回應 |
| 結論／未知 | 只描述已觀察資料；其他範圍另列 |
| 修復確認 | 越權讀取拒絕，原有正常功能通過，完成清理 |

讀者能說明「問題、如何知道、尚未知、下一步」，才是說明品質的判準。實作是否通過仍依[既有 practical 驗收](../../../assessments/practice-bank/practical.md)。
