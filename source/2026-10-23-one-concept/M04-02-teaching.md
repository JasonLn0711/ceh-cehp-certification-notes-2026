CEH｜M04-02 DNS 列舉
10/23 晚間：一次學一個核心概念

先記住一句：DNS 幫我們找出「名稱對應到哪裡」。服務是否正常、誰能登入，則要另外查核。

1. DNS 是網路的聯絡簿

你記得網站名稱，電腦需要 IP 位址。DNS 列舉就是查詢不同類型的記錄，整理網站、郵件與名稱伺服器的線索，用於授權的資產盤點與設定檢查。

「遞迴解析器」像代查人員，替你找答案，也會暫存結果；「權威伺服器」管理某個區域的正式 DNS 資料。傳統 DNS 使用 UDP 或 TCP 53，TCP 也能處理一般查詢。

2. 聯絡簿有哪些欄位？

• A／AAAA：名稱對應的 IPv4／IPv6 位址。
• CNAME：別名指向另一個名稱。
• MX：網域的收信伺服器，列的是主機而非個人信箱。
• NS：該區域的權威名稱伺服器。
• TXT：文字資料，常放網域驗證或郵件政策。
• SOA：區域管理資料，例如序號、同步時間設定。
• PTR：反向查詢 IP 對應的名稱；還要與正向記錄交叉核對。

3. 用一個例子串起來

以下是自建實驗室的合成資料，名稱與位址僅供示範，這裡並未執行查詢：

www.example.test 的 A：192.0.2.10
shop.example.test 的 CNAME：www.example.test
example.test 的 MX：10 mail.example.test

你可以整理出：網站名稱指向示範 IP；shop 是別名；郵件設定指定 mail 主機，10 是優先順序，數字越小越優先。

這些回答描述 DNS 設定。網站能否開啟、郵件是否送達、誰有管理權限，需要各自的測試或證據。

4. 查不到時，先看回應

• NXDOMAIN：此次查詢所見的名稱不存在；經過別名時，要看回應指的是哪個名稱。
• NODATA：名稱存在，但缺少所問的記錄類型。例如有 A，卻查不到 AAAA。通常以 NOERROR 搭配空答案呈現，還需看回應內容，它不是獨立錯誤碼。
• SERVFAIL：伺服器處理解析時發生問題。
• Timeout：等待期間未收到回覆，原因待查。

記下查詢時間、查哪台伺服器、名稱、記錄類型及完整回應。快取、TTL（快取有效時間）及內外網設定，都可能讓答案不同。

5. 一筆查詢，和整區複製

一般查詢像問一個欄位；AXFR「區域傳送」像複製整份區域資料，原本用來同步 DNS 伺服器。一個區域也可能只涵蓋網域的一部分。

查公開記錄與測試 AXFR，要分別確認授權範圍。練習只在明確授權的實驗環境進行。防護重點是限制區域傳送對象、設定適當驗證，並限制遞迴與快取查詢的使用者。

另外兩個相關觀念：
• Cache Snooping：從快取回應推測哪些名稱曾被查詢。共用快取與預先載入都會影響結果，個人行為還需要其他證據。
• DNSSEC：驗證 DNS 資料來源與完整性，資料保密則是另一件事。使用 NSEC 的簽署區域，也可能透露名稱之間的線索；公開資訊與存取權限仍要分別管理。

小檢核
同一台 DNS 回覆 www.example.test 的 A 是 192.0.2.10，查 AAAA 則得到 NODATA。請用一兩句話說明：目前確認了什麼？要知道網站能否開啟，還要查什麼？
