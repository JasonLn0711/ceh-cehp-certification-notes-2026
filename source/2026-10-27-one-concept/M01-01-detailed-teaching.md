## 一、先理解：資訊安全到底在保護什麼？

核心觀念：資訊安全不是只有防止駭客入侵，而是確保資訊不會被不該看的人看到、不會被不當修改，而且需要使用時能夠正常使用。

假設你是一間醫院的資訊主管。

醫院有一套電子病歷系統，裡面保存病患的姓名、檢驗數據、診斷結果與用藥紀錄。

你的工作是保護這套系統。

但「保護」究竟代表什麼？

我們可以拆成三個問題：

- 誰可以看到病歷？ 病患的敏感資料不能隨便被其他人讀取。
- 病歷內容是否可信？ 病患的血型、用藥紀錄不能遭到未經授權的修改。
- 醫師能否正常使用？ 急診醫師需要病歷時，系統不能一直無法連線。

這三個問題，就是資訊安全最基礎的三大目標。

稱為：

CIA Triad（資訊安全三要素）

這裡的 CIA 不是美國中央情報局，而是三個英文單字的縮寫。

| 英文 | 台灣常用中文 | 最重要的問題 |
| --- | --- | --- |
| Confidentiality | 機密性 | 不該看的人，有沒有看到？ |
| Integrity | 完整性 | 資料有沒有遭到不當修改或破壞？ |
| Availability | 可用性 | 有權使用的人，需要時能不能使用？ |

這三項是 NIST（美國國家標準暨技術研究院）資訊安全定義中的核心目標。[NCCoE](https://www.nccoe.nist.gov/publication/1800-26/VolA/index.html)

接下來，我們逐一理解。

## 二、Confidentiality：機密性

1. 什麼是機密性？

機密性，就是：

確保資訊只有經過授權的人才能存取，不會洩漏給未經授權的人。

想像你到醫院看診。

醫師可以查看你的病歷，但隔壁床的病患不應該因為使用同一套系統，就看到你的疾病診斷。

如果隔壁床病患可以看到你的病歷，就代表機密性出了問題。

2. 現實世界的例子

| 事件 | 是否違反機密性 |
| --- | --- |
| 醫師依照職務權限查看病歷 | 通常沒有 |
| 駭客偷走病患資料 | 是 |
| 員工把公司的機密文件寄給外部人士 | 可能是 |
| 學生偷看到其他人的考試成績 | 是 |

要特別注意：

機密性不是要求所有資料都不能被查看，而是要求只有被授權的人，才能在授權範圍內使用資料。

3. 怎麼保護機密性？

常見方法包括：

- Authentication（身分驗證）：確認使用者是誰，例如密碼或多因素驗證（MFA）。
- Authorization（授權）：確認使用者可以讀取哪些資料。
- Encryption（加密）：讓未取得解密所需金鑰的人，難以讀懂資料。
- Access Control（存取控制）：限制不同人員可以執行的操作。

例如，醫院可以規定：

醫師可以讀取職務所需的病歷，病患可以查看自己的資料，而一般訪客不可以任意查詢。

這就是機密性在實務上的應用。

## 三、Integrity：完整性

1. 什麼是完整性？

完整性，就是：

確保資料沒有遭到未經授權或不當的修改、刪除或破壞。

例如：

醫師在系統裡輸入：

「病患血型：A 型」

結果有人未經授權，把資料改成：

「病患血型：B 型」

即使這份資料完全沒有外洩，仍然構成嚴重的資訊安全問題。

因為資料的完整性已經遭到破壞。

2. 現實世界的例子

| 事件 | 是否影響完整性 |
| --- | --- |
| 駭客把考試成績從 60 分改成 90 分 | 是 |
| 惡意程式刪除公司的重要資料 | 是 |
| 醫師依正常流程修正錯誤病歷 | 不一定，通常是合法修正 |
| 攻擊者偷偷修改銀行轉帳金額 | 是 |

這裡有個重要觀念：

完整性不等於資料永遠不能修改。

例如，醫師發現原本填寫的病歷有錯誤，依照規定進行修正，通常是維護資料品質，而不是破壞完整性。

此外，完整性也不完全等於事實正確性。

一筆資料即使從來沒有被修改，也可能從一開始就輸入錯誤。

3. 怎麼保護完整性？

常見方法包括：

第一種：Hash（雜湊值）

你可以把 Hash 想像成檔案的「數位指紋」。

例如：

```text
原始資料：
考試成績 = 85

修改資料：
考試成績 = 95
```

經過 SHA-256 等雜湊演算法處理後，通常會得到完全不同的雜湊值。

因此，我們可以比較：

### 雜湊比對：先確認可信基準

同一演算法、同一份位元組資料範圍；差異不等於已證實入侵。

- 原本的 Hash：可信保存的比對基準
- 目前檔案的 Hash：重新計算待檢查的檔案
- 兩者是否相同？：不同表示內容變動；相同仍不保證原始資料符合事實。

[下載 SVG 圖解](https://learn.cs-kairos.com/images/ceh/m01-01-hash-zh.svg)

如果不同，就代表檔案內容發生變化。

但請注意：

Hash 本身主要用來偵測資料差異，不能單憑它判定誰修改了檔案，也不能直接證明發生駭客入侵。

而且原始 Hash 必須可靠地保存，否則攻擊者可能連同檢查用的 Hash 一起替換。

第二種：Audit Log（稽核紀錄）

記錄誰在什麼時間修改了資料、執行什麼操作。

第三種：Digital Signature（數位簽章）

使用密碼學機制驗證資料是否遭到修改，以及簽署者身分是否可信。

技術補充：驗證簽章還需要可信公鑰及適當的身分／憑證驗證；簽章有效不保證原始內容符合事實。

## 四、Availability：可用性

1. 什麼是可用性？

可用性，就是：

確保經過授權的人，在需要使用系統或資訊時，可以及時、可靠地取得服務。

例如：

醫院急診室有一名病患需要緊急手術。

醫師準備查看病患的過敏紀錄。

但是電子病歷系統突然當機，完全無法開啟。

這就是可用性問題。

即使：

- 沒有任何病歷外洩。
- 沒有任何資料遭到修改。
- 沒有任何駭客入侵。

系統仍然可能發生嚴重的資訊安全事件。

資訊安全問題不一定由惡意攻擊造成。

硬體故障、停電、網路中斷與人為操作失誤，也都可能影響可用性。

2. 現實世界的例子

| 事件 | 是否影響可用性 |
| --- | --- |
| 醫院電子病歷系統當機 | 是 |
| 學校考試網站無法連線 | 是 |
| 網站遭受 DDoS 攻擊，無法正常提供服務 | 是 |
| 伺服器硬碟損壞，重要資料暫時無法讀取 | 是 |

3. 怎麼保護可用性？

常見方法包括：

① Backup（備份）

定期備份資料。

當資料遺失或毀損，可以利用備份進行還原。

但要注意，只有備份不代表服務可以立即恢復。

② Redundancy（備援）

準備額外的設備或服務。

例如：

### 備援：正常服務與故障切換

使用者 → 主要伺服器；下列是兩種分支情況，不是連續執行的兩步。

- 正常 → 提供服務：主要伺服器正常時服務使用者。
- 故障 → 備援伺服器 → 繼續提供服務：必須配合健康檢查、資料同步與故障切換機制。

[下載 SVG 圖解](https://learn.cs-kairos.com/images/ceh/m01-01-failover-zh.svg)

實際上，備援還需要健康檢查、資料同步與故障切換機制，才能可靠運作。

③ Disaster Recovery（災難復原）

規劃發生重大故障後，如何恢復資料與資訊服務。

④ DDoS Protection（分散式阻斷服務攻擊防護）

降低大量惡意流量造成網站無法使用的風險。

## 五、把三個觀念串起來：同一個事件可能同時影響 CIA

技術補充：未授權加密也會改變資料，可能同時損害完整性與可用性；下表按主要影響說明，並非互斥分類。外洩仍需獨立證據。

現在我們假設一家醫院遭受勒索軟體（Ransomware）攻擊。

攻擊者可能做三件事：

| 攻擊行為 | 影響的安全目標 | 原因 |
| --- | --- | --- |
| 偷走病患資料 | Confidentiality | 未授權取得敏感資訊 |
| 刪除或竄改病歷 | Integrity | 破壞資料完整性 |
| 加密病歷，使醫師無法讀取 | Availability | 阻礙正常使用 |

注意第三個行為：

勒索軟體將檔案加密，使醫師無法使用，明確影響可用性；但不能只因檔案遭到加密，就推論病患資料一定已經外洩。

是否發生外洩，需要另外調查。

因此，CIA Triad 不是要求你把每個事件硬塞進單一類別。

真正重要的是判斷：

一個事件分別對機密性、完整性與可用性造成了什麼影響？

## 六、CEH 實務應用：資安工程師怎麼判斷？

假設你是某間學校的資安工程師。

校方告訴你：

「我們的成績系統好像出問題了。」

你不能立刻認定是駭客入侵。

正確方法是分三個面向調查。

| 調查方向 | 要回答的問題 | 可以蒐集的證據 |
| --- | --- | --- |
| 機密性 C | 有沒有未經授權的人讀取成績？ | 存取紀錄、下載紀錄、權限設定 |
| 完整性 I | 有沒有成績遭到不當修改？ | 資料異動紀錄、版本紀錄、Hash |
| 可用性 A | 老師及學生能否正常使用系統？ | 系統監控、錯誤紀錄、網路連線狀態 |

這個方法非常重要，因為它可以讓你從「猜測問題」轉變成「根據證據判斷問題」。

不過，必須區分兩件事：

調查方向不等於調查結論。

例如，系統紀錄顯示有人登入，不一定代表他讀取了敏感資料；系統出現錯誤，也不一定代表有人攻擊。

我們還需要進一步核對證據。

## 七、兩分鐘 Ubuntu 小實驗：親眼觀察完整性

操作補充：只在自己的練習資料夾執行。下方 > 會覆寫同名 grades.csv；若已有檔案，先換新的練習目錄。85 改成 95 實際只改一個字元，原文「兩個數字」指修改前後的兩個數值。結束後可手動刪除本次建立的練習檔，不要刪除其他資料。

我們用一個安全的小實驗來驗證 Integrity。

你可以在自己的 Ubuntu 24.04 練習環境執行。

步驟一：建立練習檔案

開啟 Terminal（終端機），輸入：

```text
mkdir -p ~/ceh-m01-01
cd ~/ceh-m01-01

printf "student_id,score\ns001,85\n" > grades.csv
```

指令說明：

- mkdir -p：建立練習資料夾。
- cd：切換到該資料夾。
- printf：輸出指定文字。
- >：將輸出寫入檔案。
- grades.csv：我們建立的模擬成績檔。

接著查看檔案內容：

```text
cat grades.csv
```

預期結果：

```text
student_id,score
s001,85
```

步驟二：計算檔案的 Hash

執行：

```text
sha256sum grades.csv
```

系統會輸出類似：

```text
<64個十六進位字元>  grades.csv
```

這個 64 字元的結果，就是 SHA-256 雜湊值。

它會根據檔案內容產生。

步驟三：修改成績

執行：

```text
sed -i 's/85/95/' grades.csv
```

這個指令會把檔案中的 85 改成 95。

其中：

- sed：文字處理工具。
- -i：直接修改檔案。
- s/85/95/：將符合的文字從 85 取代成 95。

這只是我們自己建立的練習檔案，不涉及任何真實成績。

步驟四：重新計算 Hash

再次執行：

```text
sha256sum grades.csv
```

比較修改前後的結果。

你會觀察到：

即使只修改兩個數字，檔案的 SHA-256 雜湊值也會改變。

這就是雜湊值協助偵測資料變動的基本原理。

但它不會告訴我們修改是否合法，也不會自動阻止修改。

因此，實務上還需要搭配權限控管、異動紀錄與可信任的比對基準。

## 八、考試重點：三個容易混淆的觀念

| 常見誤解 | 正確認知 |
| --- | --- |
| 有加密就代表資訊安全 | 加密主要保護機密性，不能單靠加密確保所有 CIA 目標 |
| 資料沒有外洩就代表安全 | 資料仍可能遭到竄改，或無法正常使用 |
| 發生資安事件就代表有駭客 | 系統故障、人為疏失也可能影響資訊安全 |

另外，請記住：

CIA Triad 是資訊安全的目標框架，不是駭客攻擊的步驟。

這個區別會直接連接到下一堂 CEH M01-02。

我們先定義需要保護的目標，再辨認資產、威脅、弱點與風險，最後決定如何保護系統。

概念流程如下：

### 從資訊資產到持續改善

簡化的思考順序；實際工作需要反覆檢查與調整。

- 資訊資產：確認需要保護什麼
- CIA Triad：Confidentiality／Integrity／Availability
- 辨認威脅與弱點：評估風險
- 選擇適當的安全控制措施：持續監控與改善

本課總結

記住這三句話，就掌握了 CEH M01-01 最核心的知識：

C — Confidentiality：不該看的人，不能看。

I — Integrity：資料不能遭到不當修改或破壞。

A — Availability：有權使用的人，需要時要能使用。

最重要的能力不是背出 CIA 三個英文單字，而是看到真實事件時，能夠辨識哪些安全目標受到影響，並且知道應該蒐集什麼證據。
