## Frame 17 — Follow a normal TCP handshake

- status: animated
- src: compositions/S17.html
- duration: 75.700000000s
- transition_in: cut
- scene: Connection establishment can require temporary server state before completion.
- rules: svg-path-draw, css-marker-patterns
- voiceover: Transmission Control Protocol, or T C P, establishes a connection with a three message exchange in the ordinary example shown here. Synchronize marks the client's opening request and carries its starting sequence information. The server responds with its own synchronize information and an acknowledgment of the client's opening. Acknowledge marks the client's confirming reply. The server can then regard the connection as established. Pending state represents the server's temporary bookkeeping while it awaits that confirmation. This is a simplified normal handshake; the protocol also handles retransmission and other valid situations. The exchange coordinates sequence information. It does not authenticate the human using the connection. A completed handshake also does not prove that a later application request is harmless. For availability analysis, notice the timing of resource commitment. Depending on the implementation and active defenses, a server may reserve resources before the final confirmation arrives. That gap creates the connection state question we will examine next. Tally keeps the pending box separate from the established box so completed connections and incomplete attempts are never silently counted as the same thing.
